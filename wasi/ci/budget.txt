# The artifact's size ceiling.
#
#   state: <awaiting-packaging | packaged | ready-to-publish | shipped>
#   ceiling_bytes: <n>
#   set_from: <what was measured, where>
#
# `set_from` is the measurement the number came from. A ceiling without one is a wish, so
# `check-size.sh` fails on a missing `set_from` rather than on the artifact.
#
# A ceiling is set from the **worst** measurement, rounded up: a number set to the best run
# fires on a dependency bump and is deleted within a week, and a deleted ceiling is worse
# than none because the gate still reports success.
#
# Measured 2026-11-08 on wasm32-wasip1, rustc 1.9x, `-C panic=abort`, from a clean
# `cargo build --release`: 2 158 771 bytes unstripped; the artifact that ships is 1 896 139 bytes,
# because the `name` custom section (the debug symbol table) is **removed** and it was 261 595 B
# of the module. Two numbers, and the distinction matters for the ceiling below: the removed
# section is not the artifact's size (#1474). The
# ceiling is the stripped measurement rounded up to the next 100 KiB: room for one dependency's
# debug strings and nothing structural, and **lowered** from the unstripped number rather than
# left as headroom nobody needs.
#
# It is deliberately not "the smallest we have seen": this artifact is a cdylib over the whole
# portable slice, so a size that only holds at the best measurement is not a ceiling.
state: packaged
ceiling_bytes: 1945600
set_from: "2026-11-09, wasm32-wasip1 release build with --remap-path-prefix and the name section stripped: 1896139 bytes shipped (2157734 unstripped, 261595 removed); was 1896192 before #1477"

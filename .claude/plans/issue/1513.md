# #1513 (DOC-1) — public text may name only repositories the organisation publishes

Branch `issue/1513`. Single issue, no grouping: it is the only open one in its area, and its
subject (what this tree may name) is not shared with #1512 (which vocabulary the spec enumerates).

## The premise moved while the issue was open

The issue proposes an allowlist so that a **private** repository's name fails by absence. Its own
example was `rigorix-sdk`, which the tree called "same-owner private". Measured 2026-11-11:

| repository | `gh repo view --json visibility` | anonymous `GET https://github.com/…` |
|---|---|---|
| `rigorix-oss` | PUBLIC | 200 |
| `rigorix-sdk` | **PUBLIC**, pushed 2026-11-11T16:33Z | **200** |
| the private enterprise repository | **PRIVATE** | **404** |

and `rigorix-verifier` 0.10.0 is anonymously installable (crates.io 200 with a UA, PyPI 200,
npm 200). So `rigorix-sdk` is a public reference and the literal in `ci.yml` is not a disclosure.
That repository is named — in `.github/workflows/anchor-e2e.yml`, functionally, and in 33 files of
prose. **The registry decides, not a hardcoded pattern**: the check's subject list is
`.pi/public-repositories.tsv`, so a name flips from finding to pass by editing one row.

## Work

1. **`.pi/public-repositories.tsv`** — the registry, and the guard's only subject list. One row per
   name: `token`, `kind`, `evidence`. Kinds: `repository` (must carry a measured `gh repo view`/
   `gh repo list` result and the word PUBLIC — a row typed from memory is refused), `artifact`
   (a published package, measured by HTTP status), `workspace-package`, `proposed-crate`,
   `rejected`, `identifier` (a fixture, env prefix, hook name, script name — not a name anyone
   owns). Globs are allowed so a fixture family is one row.
2. **`.pi/scripts/validate-public-references.sh`** — every repository-shaped token in governed
   text must be in the registry; a token that is not fails naming `file:line: token` and saying
   what to write instead. Governed = `.md`, `.tsv`, `.yml`, `.yaml`: prose and configuration,
   where a claim is made. Code files are out (a temp-directory fixture in `engine/src/**` is not a
   claim about whose repository something is) — stated in the script so the hole is named.
3. **The workflow** — `anchor-e2e.yml` names the private repository literally, with a PAT in the
   clone URL. `${{ vars.ENTERPRISE_REPOSITORY }}` for owner/name, clone path `$RUNNER_TEMP/enterprise`,
   `ENTERPRISE_DIR` likewise, and a comment naming the symptom when the variable is unset. The
   clean skip and `workflow_dispatch` + weekly schedule stay: the job must not run on PRs.
4. **`ci.yml`** — three claims corrected: "rigorix-sdk is same-owner private" (false today), and
   `token: ${{ secrets.RIGORIX_SDK_TOKEN }}` deleted, because a public repository clones with the
   workflow's own `contents: read`. That also lets the conformance job run on fork PRs, where no
   secret exists, instead of failing as an infra error. `repository:`, `path:`, `ref: main`,
   `RIGORIX_SDK_SCHEMAS` and `--manifest-path` stay — they are correct and cross-repo named in
   the SDK's own release docs.
5. **`.github/ci-affected.tsv`** — delete the `rigorix-sdk/**` row: no diff in this repository can
   contain that path, so it can never match, while `.github/**` (ALL) and `schemas/**` already
   select `conformance`.
6. **The sweep** — the private repository's name, and the two proposed crates that carry it as a prefix, are
   rewritten to public-safe wording in all 33 files; `demo/anchor-e2e/{run.sh,docker-compose.yml}`
   default to `../enterprise` so the local path matches the workflow's.

## Why it is worth a script

The same defect appeared in five files across three subject areas, each written by someone who knew
the rule at the time. A reviewer reading a diff for correctness does not re-read it for
confidentiality; a check does.

## Acceptance

| # | Criterion | Command | Expected |
|---|---|---|---|
| 1 | the tree passes | `bash .pi/scripts/validate-public-references.sh` | exit 0, every token registered |
| 2 | an unknown token fails | plant an unregistered `rigorix-…` name and the private repository's name in a workflow copy | exit 1 naming file:line: token |
| 3 | a registered name passes | plant `rigorix-sdk` | exit 0 |
| 4 | crate names are not repositories | `rigorix-verifier` in prose | passes (kind `artifact`) |
| 5 | a `*-demo` that is not published fails | plant `nobody-demo` | exit 1 |
| 6 | the registry is evidence, not memory | a `repository` row without a measured result | exit 2 |
| 7 | it is registered | `.pi/guards.tsv` | gating, `run_here=yes` |
| 8 | no workflow exemption | the check's governed set | includes `.github/workflows/**` |
| 9 | conformance is green without the PAT | the `📐 SDK-schema conformance` job on this PR | green, `RIGORIX_SDK_TOKEN` absent |
| 10 | `anchor-e2e.yml` parses | `.github/scripts/validate-workflows.sh` | pass |

## Out of scope

- The private-side denylist: writing the private names into a public file is the leak it prevents.
- git history: the name is in commits that predate this branch. Removing it there is a rewrite
  decision, not a docs sweep.
- `RIGORIX_SDK_TOKEN`'s name in the repository's secret list: a secret's name cannot be read back
  or rewritten by a script, and after this change nothing in the tree uses it.

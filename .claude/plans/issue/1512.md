# #1512 — the specification's vocabularies against their owners in code

## The premise moved again: the document was restructured

The issue cites `docs/spec/consequence-gating-v2.md` §2.3, §2.6, §3.1. That file no longer exists at
`c2a7b0f`-era `main`: the specification is now `docs/spec/execution-governance/03-requirements.md`,
and the vocabularies live in **§L** (the gate table's "Identifier in the record" column) and
**RS-111** (the refusal table, whose rows group words with `·` rather than naming variants). So the
check is written against the tables that exist, not against section numbers that do not.

## Implemented

`engine/.pi/scripts/validate-spec-vocabulary.sh` — two vocabularies, compared as sets in both
directions, naming the word:

| vocabulary | document | owner | result |
|---|---|---|---|
| gate identifiers | §L, "Identifier in the record" (Approval's row says "—", and is skipped because it carries none) | `GateId::as_str` | 4 = 4 |
| refusal wire words | RS-111 | `RefusalKind::as_str` | 15 = 15 |

A code-only kind reports *"a new kind needs a specification version that names it (RS-108), not a
table row"*; a document-only word reports that the document names something the code cannot produce.
Exit 2 is malformed input (no table, no `as_str` body), exit 1 is divergence — different remedies.

Six seeds: control, spec-only word, code-only kind, one word respelled in one place, a gate row
removed, a document with no table (malformed). Registered gating, `run_here=yes`, and declared in
`.pi/guard-subjects.tsv` so the affected-path map keeps it fed.

## The third vocabulary has no owner in the document

RS-108 names three vocabularies ("a refusal kind, an evidence kind, or a gate identifier"). The
current document enumerates two. The eight `EvidenceKind` variants appear nowhere under `docs/spec/`
after the restructure — checked with `git grep` for each word. A comparison needs two sides, so the
guard reports the gap in `--report` and does not invent a table. Tracked separately.

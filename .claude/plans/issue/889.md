## Intent

Add a bundle-ingestion path so the OSS engine can build a `SequencePolicyConfig`
from the enterprise-exported `policy.json` v1 JSON (root surface: `fail_closed`
+ `rules` + `requirements`), alongside the existing operator-authored
`.rigorix/sequence-policy.toml`. Prove, with a conformance round-trip, that the
bundle and the equivalent local TOML produce **identical** verdicts
(deny / promote / allow), with `rule_id` + `step` asserted.

## Design decisions

1. **Reuse the existing validator — no parallel one.** Parse the bundle JSON
   straight into `SequencePolicyConfig` (its serde field names already match the
   SDK `policy.json` shape: `fail_closed`, `rules`, `requirements`, lowercase
   `action`, `match` rename, `equals_step`) and then call the same
   `validate_with_default_caps()` the TOML path uses. Any divergence is
   impossible by construction.
2. **Separate source, not the `EnforcementConfigProvider` seam.** Sequence
   policy is a *separate* config from `EnforcementConfig`. A sibling
   `BundleSequencePolicyRepository` reads the bundle JSON (inline or from a
   file the composition root fetched). The existing provider is untouched.
3. **Absent vs invalid is explicit.** No bundle configured / empty → `Ok(None)`
   (fail-open-absent, status quo). Bundle present but unparseable / over-cap /
   not the policy.json root shape → `Err` (fail closed).
4. **Precedence is configurable and fail-closed by default policy.**
   - `EnterpriseWins` (**default**) — the bundle is the source of truth; a
     shadowed local TOML is logged. This is the documented safe default.
   - `LocalWins` — explicit logged override for offline / debugging.
   - `RefuseOnConflict` — if both are present and differ, refuse to start
     (fail closed), never guess and never merge.
   Every parse/validation error fails closed regardless of precedence.

# #1498 (SINK-11) — a git step is a code-execution surface, so it declares its boundary

**Branch:** `issue/1498` (single issue; no grouping — one coherent change, one mechanism)
**Priority:** high. **Exposure:** reachable — any `git_read` step, no declaration required.

## The defect, measured

`exec_git_read` splits the step's `args` on whitespace and hands the argv to `git` through
`git_output` (resolved program, argv, cleared env — all correct). None of that constrains *what
git does with the argv*, and git's argv can name a program:

```
$ git -c alias.pwn='!touch /tmp/x/PWNED' pwn        → PWNED created
```

A `!`-prefixed alias runs through a shell. `split_whitespace` is not a constraint on it: `!curl`
plus ordinary arguments is a download. So a `git_read` step ran arbitrary programs in the
engine's filesystem — and unlike `run_command`, it needed **no** `RIGORIX_SANDBOX`, which made
ADR-017's "cannot execute a `run_command` step" true and materially misleading.

## Order

1. `shell_policy::validate_git_read_args` — read-subcommand allowlist + the program-naming forms
   refused **by name**.
2. `EXECUTING_STEP_KINDS` + one `undeclared_step_refusal` — the gate keyed on the capability,
   both dispatch routes, with a structural test that a new spawning handler must be in the list.
3. `git add -- path` so a path is never read as an option.
4. The record: ADR-023 §6.4 rewritten with the proven primitive (not the pager), the row's
   `requires`/`does_not`, ADR-017's amendment, `docs/deployment.md`, CHANGELOG.

## Acceptance

| # | Criterion | Proof |
|---|---|---|
| 1 | `-c alias.pwn=!touch` refused | `a_git_read_step_cannot_name_a_program`, marker absent |
| 2 | the `!curl` form refused before spawn | same test, same assertion |
| 3 | ordinary reads still work | `an_ordinary_git_read_step_still_runs` |
| 4 | a git step declares its boundary | `a_git_step_without_a_declaration_is_refused_before_any_spawn` + `every_spawning_step_kind_is_gated` |
| 5 | the record is accurate | `grep -n pager ADR-023` — replaced by the proven command |

## What this does not do

- It does not remove the workspace path: an alias in `.git/config` or a hook in `.git/hooks` is
  code the agent can write, and `.git` is not `.rigorix`. The declared isolation is the boundary
  there — recorded in ADR-023 §6.4 and in the row's `does_not`.
- It does not make `split_whitespace` a parser. The allowlist constrains the first token and the
  refused forms; it does not give git a structured argv.
- Out of scope per the issue: `git_read_tool.rs`, which builds a fixed argv and is not reachable
  from a plan step.

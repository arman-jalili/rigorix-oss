## Not done — the tier stayed `advisory`, because the premise it rests on is false

The issue asks for `tier=gating`, whose meaning in that file is "a non-zero exit fails a mandatory
build path". Measured:

```
hardening.yml:91,117,157,186   continue-on-error: true     (every validator loop)
hardening.yml:106,132,169      bash "$script" || true
ci.yml                          no invocation of validate-security.sh at all
local-ci.sh:265                 run_cmd "cargo audit" cargo audit --deny warnings   (real exit code)
local-ci.sh:284                 run_script … validate-security.sh                   (real exit code)
```

So a non-zero exit from this script fails **no CI job**; it gates locally. `gating` would be a
statement about a job that does not exist — and the registry's own `--list` would print "gates via a
dedicated CI job", which is precisely what is not true. The issue excludes changing `hardening.yml`,
and that is the only way to make `gating` true (a step that runs the validator with a real exit
code). Recorded in the note instead, with both halves named, and left as the operator's call.

## The fix introduced a regression that only `local-ci` could see

Making the script fail on an audit failure exposed a second copy of #1530's defect: `TREE_ROOT` is the
*crate* when the script runs from `engine/`, and the audit's subject is the workspace lockfile, so
the per-crate run answered `Couldn't load Cargo.lock` and — now failing — failed for the wrong
reason. `local-ci.sh` caught it on all four crates:

```
  ❌ FAIL validate-security.sh (engine) (exit: 1)
  ❌ FAIL validate-security.sh (mcp) (exit: 1)   …
  ❌ CI SIMULATION FAILED — 4 check(s) failed
```

**CI could not see it**, because `hardening.yml` runs every validator with `continue-on-error: true`
and `|| true`. That is the argument for the tier change the issue asked for, from the other side: not
just "a non-zero exit fails nothing" but "the thing CI is blind to is exactly the thing that broke".
Fixed by resolving the workspace root; `local-ci` then reports **120 checks, 0 failed**.
